# UI redesign audit

Baseline: 0334dcf. Applied repository-local meshwall-ui-ux skill.

Findings: per-tile controls consumed screen area and became unreadable at 10 columns; toolbar lacked grouping and status/group filters; drag reorder had no keyboard alternative; offline and no-frame surfaces looked similar; nav could not collapse; device empty states and form labels were inconsistent.

Changes: compact shell and collapsible navigation, shared CSS tokens, clear overview metrics and workflow; two-row wall toolbar with layout management, counts, group/status filters; selected-tile inspector for start/stop, monitors, focus/fullscreen, size and keyboard move; 1–10 desired columns with responsive effective count; lightweight tiles with text states, explicit no-screen placeholder and last draw time; grouped table actions and empty states; aligned setup wizard styling. Full-wall fullscreen and distinct ended/no-session/error labels. Screenshot review showed excess mobile navigation height; mobile navigation now defaults to collapsed independently of desktop, retaining the account action. No external fonts/frameworks. Existing permissions and consent preserved; no automatic screen session starts. Layout remains local per account.

Verification: visual.yml captures baseline and after screenshots with synthetic inventory and checks 1920×1080, 1440×900, 1280×720, 768×1024 and 390×844, densities 1/4/16/50/100, overflow, selection, resize, reorder, focus, filters and saved preset. CI artifacts contain no real screen content. See GitHub Actions for actual outcomes. The same workflow checks all management pages at desktop/mobile and the actual local setup HTTP server with a mocked preflight/install callback at five widths. Setup retry disables submission after failed checks; stage indicators reflect actual fixture responses. Static/unit and real loopback integration workflows remain separate.

Palette check: selected text/panel and button colors exceed 4.5:1; the control border was increased from 2.27:1 to 3.37:1 against raised surfaces. Automated token-pair checks run with the unit suite. Pending: independent WCAG manual/screen reader audit, light theme, live agent display/consent/monitor switching, 100 simultaneous live streams and HG680P/B860H benchmarks. Native compatibility panels, Tailscale prerequisites, fresh Windows install and maintenance/rollback gaps remain as documented in AUDIT.md. A passing visual fixture is not production readiness.

Account management addition: standard account dialog, direct view-only grant/revoke controls, engine readback and inherited-rights warning. Visual fixture covers the dialog at 1440 and 390 pixels with keyboard dismissal and focus return. Real-engine CI tests account creation and direct membership changes; no actual desktop permission test yet.


Guided adoption review: the disposable local layout fixture covers discovered and manual paths, keyboard preview and checkbox operation, invalid and accepted backup directories, invalidated plans after editing, and an existing-file collision. Chromium checks the five standard viewports. Side-by-side setup screenshots exposed misleading fresh-install stages in the adoption flow. The wizard now hides the fresh-install stages and credential form when it recognizes an existing installation. Desktop/mobile review covered the preflight, terminal handoff and collision states. See the [visual workflow](https://github.com/el-utama/Mesh-Wall/actions/runs/45957955276) for fixture evidence, including five viewports.

Read-only service inspection exposes the named service account and current state inside the adoption review. The wizard fixture exercises keyboard submission, a mismatched registered service and a service that changes during backup-path review. In the latter state the terminal handoff is hidden, focus returns to the service check, and the detailed error appears beside the service field. The browser fixture uses simulated service metadata.
